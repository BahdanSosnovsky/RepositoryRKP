1. ЧТО СДЕЛАНО (КРАТКО)
--------------------------------------------------------------------------------
Одностраничное веб-приложение (SPA) для аптеки:

  - страница АВТОРИЗАЦИИ (/login) — вход по логину и паролю;
  - страница РЕГИСТРАЦИИ (/register) — создание нового аккаунта;
  - страница ПРОСМОТРА (/) — таблица лекарств с добавлением и удалением строк;
  - навигация, которая меняется в зависимости от того, вошёл ли пользователь;
  - данные хранятся в «заглушках» (в памяти браузера), настоящего сервера нет.

Технологии:
  - React 19 — библиотека для построения интерфейса из компонентов;
  - Vite — сборщик и сервер разработки;
  - React Router (react-router-dom) — маршрутизация (переходы между страницами);
  - JavaScript (JSX), без TypeScript.

2. ЗАДАНИЕ И КАК ОНО ВЫПОЛНЕНО
--------------------------------------------------------------------------------
Формулировка задания:
  «Добавить объект с данными об аккаунтах пользователей. Организовать хранение
  информации об авторизовавшемся пользователе в state корневого компонента.
  Используя React Router организовать переход со страницы авторизации к странице
  просмотра, разработанной на предыдущей лабораторной работе.»

  ТРЕБОВАНИЕ 1. «Объект с данными об аккаунтах пользователей».
    -> Файл src/services/AccountService.js. Класс AccountService хранит список
       аккаунтов (admin / user) и умеет проверять логин и пароль. Экземпляр
       этого класса (accountService) и есть «объект с данными об аккаунтах».
       Сам аккаунт описывает класс Account (src/models/Account.js).

  ТРЕБОВАНИЕ 2. «Хранение информации об авторизовавшемся пользователе
                 в state корневого компонента».
    -> Файл src/App.jsx. Корневой компонент App содержит
       const [currentUser, setCurrentUser] = useState(null).
       Пока никто не вошёл — там null, после входа — объект Account.

  ТРЕБОВАНИЕ 3. «Используя React Router организовать переход со страницы
                 авторизации к странице просмотра».
    -> Файл src/pages/LoginPage.jsx. После успешной проверки логина и пароля
       вызывается navigate('/') (хук useNavigate из React Router) —
       браузер переходит на страницу с таблицей лекарств.
       Сами маршруты описаны в src/App.jsx (Routes / Route).

  «Страница просмотра, разработанная на предыдущей лабораторной» —
    это таблица лекарств (src/pages/HomePage.jsx) с компонентами
    MedicineTable и AddMedicineForm.

5. КАК РАБОТАЕТ ПРИЛОЖЕНИЕ (ОБЩАЯ СХЕМА)
--------------------------------------------------------------------------------
1) Браузер открывает index.html. В нём есть <div id="root"></div> и скрипт
   <script type="module" src="/src/main.jsx">.

2) main.jsx создаёт корень React (createRoot) и рисует в #root компонент App,
   обёрнутый в <BrowserRouter>. BrowserRouter «слушает» адресную строку
   браузера и сообщает всем компонентам, какой сейчас адрес.

3) App.jsx:
     - создаёт state currentUser (null);
     - всегда показывает <Nav> (он стоит вне <Routes>);
     - внутри <Routes> выбирает страницу по адресу:
         "/"         -> HomePage (если вошёл) или перенаправление на /login
         "/login"    -> LoginPage
         "/register" -> RegisterPage
         остальное   -> перенаправление на "/"

4) Страницы работают с сервисами (AccountService, MedicineService), а сервисы
   хранят данные в обычных массивах в памяти.

5) Когда state меняется (setCurrentUser, setMedicines и т.д.), React
   автоматически перерисовывает затронутые компоненты.

Поток данных в React односторонний:
   ДАННЫЕ идут ВНИЗ от родителя к детям через props,
   СОБЫТИЯ идут ВВЕРХ через функции, переданные в props (onLogin, onDelete, ...).

6. REACT: КОМПОНЕНТЫ, JSX, PROPS
--------------------------------------------------------------------------------
КОМПОНЕНТ — это JavaScript-функция, которая возвращает разметку (JSX).
Имя компонента всегда с большой буквы (App, Nav, HomePage). Компонент можно
использовать как HTML-тег: <Nav />, <HomePage />.

JSX — синтаксис, похожий на HTML, внутри JavaScript. Отличия от HTML:
  - class пишется className, атрибуты — camelCase (onClick, onChange);
  - JavaScript-выражения вставляются в фигурных скобках: {currentUser.name};
  - комментарии внутри разметки: {/* комментарий */};
  - у компонента должен быть ОДИН корневой элемент (или фрагмент <> ... </>).

PROPS — параметры компонента (как аргументы функции). Родитель передаёт их
как атрибуты, ребёнок получает одним объектом и обычно сразу деструктурирует:

   <Nav currentUser={currentUser} onLogout={handleLogout} />       (в App.jsx)
   export default function Nav({ currentUser, onLogout }) { ... }  (в Nav.jsx)

Props нельзя изменять внутри ребёнка — они только для чтения.

УСЛОВНЫЙ РЕНДЕР — показать одно или другое в зависимости от условия:
   {currentUser ? <A /> : <B />}     — тернарный оператор (Nav.jsx)
   {error && <p>{error}</p>}         — показать, только если error не пустая
                                       строка (LoginPage, RegisterPage)

СПИСКИ: массив превращается в набор элементов через map, у каждого элемента
обязателен уникальный key (MedicineTable.jsx: key={item.id}). По key React
понимает, какая строка добавилась/удалилась, и не перерисовывает всё подряд.

ФРАГМЕНТ <>...</> — «невидимая обёртка»: позволяет вернуть несколько элементов
без лишнего тега в DOM (в MedicineTable он нужен, чтобы вернуть набор <tr>).

7. ХУКИ (ПОДРОБНО)
--------------------------------------------------------------------------------
ЧТО ТАКОЕ ХУК
  Хук — специальная функция React (имя начинается с use), которая даёт
  функциональному компоненту «возможности»: хранить данные, реагировать на
  жизненный цикл, получать доступ к роутеру и т.д. Правила хуков:
    1) вызывать только на верхнем уровне компонента (не внутри if, циклов
       и вложенных функций);
    2) вызывать только в компонентах или в других хуках;
    3) порядок вызова хуков не должен меняться между перерисовками.

В проекте используются два хука: useState (из react) и useNavigate
(из react-router-dom).

--- 7.1 useState -----------------------------------------------------------
Синтаксис:
   const [значение, функцияИзменения] = useState(начальноеЗначение)

Что делает:
  - хранит данные внутри компонента между перерисовками (обычная переменная
    внутри функции-компонента «забывается» при каждой перерисовке, state — нет);
  - при вызове функции изменения React сохраняет новое значение и ПЕРЕРИСОВЫВАЕТ
    компонент (и его детей).

Важные правила:
  - state нельзя менять напрямую (currentUser = ...). Только через
    setCurrentUser(...), иначе React не узнает об изменении;
  - для массивов и объектов нужно передавать НОВЫЙ массив/объект, а не менять
    старый. React сравнивает ссылки: если ссылка та же — перерисовки не будет.
    Поэтому в MedicineService add() делает [...старый, новый], а delete()
    использует filter() — оба создают новый массив.

Где useState используется в проекте:

  App.jsx
     const [currentUser, setCurrentUser] = useState(null)
     — авторизованный пользователь (ГЛАВНОЕ ТРЕБОВАНИЕ ЗАДАНИЯ).

  HomePage.jsx
     const [medicines, setMedicines] = useState(medicineService.all())
     — список лекарств, который отображается в таблице. После add/delete
       вызывается setMedicines(medicineService.all()) — таблица перерисовывается.

  AddMedicineForm.jsx
     name, price, quantity — значения трёх полей ввода.

  LoginPage.jsx
     login, password — значения полей; error — текст ошибки.

  RegisterPage.jsx
     name, login, password — значения полей; error — текст ошибки.

УПРАВЛЯЕМЫЕ ПОЛЯ ВВОДА (controlled inputs)
  <input value={login} onChange={(e) => setLogin(e.target.value)} />
  Значение поля хранится в state (value={login}), а при каждом нажатии клавиши
  onChange кладёт новый текст в state. Так React всегда «знает» содержимое поля,
  и его легко проверить, очистить (setLogin('')) или отправить.

--- 7.2 useNavigate --------------------------------------------------------
Хук из react-router-dom. Возвращает функцию для перехода на другой маршрут
ИЗ КОДА (а не по клику на ссылку):

   const navigate = useNavigate()
   navigate('/')          // перейти на главную (таблица)
   navigate('/login')     // перейти на страницу входа

Где используется:
  LoginPage.jsx    — после успешной авторизации: navigate('/')
                     (это и есть «переход со страницы авторизации к странице
                      просмотра» из задания);
  RegisterPage.jsx — после успешной регистрации: navigate('/login').

Когда нужен useNavigate, а когда Link:
  Link/Navigate — когда переход известен заранее (ссылка в меню, редирект);
  useNavigate   — когда переход надо сделать ПОСЛЕ какого-то действия
                  (проверили пароль -> перешли).

--- 7.3 Почему не использован useEffect ------------------------------------
useEffect нужен для «побочных эффектов» (запросы на сервер, таймеры, подписки).
В проекте данные берутся синхронно из заглушек, поэтому useEffect не требуется.
(Если бы данные загружались с настоящего сервера, загрузку списка лекарств
 выполняли бы в useEffect при открытии страницы.)

8. REACT ROUTER (ПОДРОБНО)
--------------------------------------------------------------------------------
Зачем: в SPA вся страница одна (index.html), но пользователь должен видеть
разные «страницы» с разными адресами (/login, /register, /). React Router
подменяет содержимое на экране в зависимости от адреса в браузере, не
перезагружая страницу.

Используемые элементы (пакет react-router-dom):

  <BrowserRouter>   (main.jsx)
      Включает маршрутизацию для всего приложения. Использует стандартный
      History API браузера, поэтому адреса обычные (/login), без #.
      Должен оборачивать всё приложение.

  <Routes> и <Route>   (App.jsx)
      <Routes> — контейнер со списком маршрутов; выбирает ОДИН подходящий.
      <Route path="/login" element={<LoginPage ... />} /> — «если адрес
      /login, показать компонент LoginPage».

  <Link to="/login">   (Nav.jsx)
      Ссылка для перехода между страницами БЕЗ перезагрузки браузера
      (обычный <a href> перезагрузил бы страницу и сбросил state).

  <Navigate to="/login" replace />   (App.jsx)
      Компонент-перенаправление. При отрисовке сразу отправляет на другой
      адрес. replace — заменяет текущую запись в истории браузера, чтобы по
      кнопке «Назад» не возвращаться на страницу, которая снова перекинет.

  useNavigate()   (LoginPage.jsx, RegisterPage.jsx)
      Хук для перехода из кода (см. раздел 7.2).

Таблица маршрутов (App.jsx):

  Адрес        | Что показывается                    | Примечание
  -------------+-------------------------------------+--------------------------
  /            | HomePage (таблица лекарств)         | только для вошедших;
               |                                     | иначе -> /login
  /login       | LoginPage (авторизация)             | после входа -> /
  /register    | RegisterPage (регистрация)          | после регистрации -> /login
  * (любой     | перенаправление на /                | защита от несуществующих
  другой)      |                                     | адресов

ЗАЩИЩЁННЫЙ МАРШРУТ (реализован в App.jsx):
   element={currentUser ? <HomePage /> : <Navigate to="/login" replace />}
   Если пользователь не авторизован, таблицу он не увидит — его отправят на
   страницу входа. Проверка основана на state currentUser из корневого
   компонента.

ПОЧЕМУ Nav СТОИТ ВНЕ <Routes>
   Всё, что вне <Routes>, показывается на каждой странице. Навигация нужна
   везде, поэтому она вынесена наружу.

9. STATE КОРНЕВОГО КОМПОНЕНТА (АВТОРИЗОВАВШИЙСЯ ПОЛЬЗОВАТЕЛЬ)
--------------------------------------------------------------------------------
Корневой компонент — App (src/App.jsx). В нём:

   const [currentUser, setCurrentUser] = useState(null)
   const handleLogin  = (account) => setCurrentUser(account)
   const handleLogout = () => setCurrentUser(null)

ЗАЧЕМ ХРАНИТЬ ИМЕННО В КОРНЕ («поднятие состояния», lifting state up)
  Информация о пользователе нужна сразу нескольким местам:
    - Nav      — показать имя и кнопку «Выйти» или ссылки «Войти/Регистрация»;
    - маршрут "/" — решить, пускать на страницу или перенаправить;
    - LoginPage — ИЗМЕНИТЬ состояние (сообщить, что пользователь вошёл).
  Эти компоненты — «соседи», друг другу данные напрямую не передают. Общий
  родитель — App, поэтому state живёт там и раздаётся вниз через props.

КАК ИДЁТ ДАННЫЕ
  Вход:
    LoginPage --onLogin(account)--> App.handleLogin --> setCurrentUser(account)
                                                          |
    App перерисовывается, передаёт новый currentUser в Nav и в маршруты <---+

  Выход:
    Nav --onLogout()--> App.handleLogout --> setCurrentUser(null)
    Маршрут "/" теперь видит null и перенаправляет на /login.

  Данные вниз:   App --currentUser--> Nav
  События вверх: LoginPage --onLogin--> App;  Nav --onLogout--> App


--------------------------------------------------------------------------------
10. ДАННЫЕ ОБ АККАУНТАХ И ЛЕКАРСТВАХ (МОДЕЛИ И СЕРВИСЫ, ООП)
--------------------------------------------------------------------------------
МОДЕЛЬ — класс, описывающий форму данных.
   Medicine: id, name, price, quantity.
   Account:  login, password, name.
   У класса есть конструктор, который заполняет поля при создании объекта:
   new Account('admin', 'admin123', 'Администратор').

СЕРВИС-ЗАГЛУШКА — класс, который хранит данные и умеет с ними работать.
Настоящего бэкенда нет, поэтому сервис имитирует его: данные лежат в массиве
в памяти браузера (при обновлении страницы сбрасываются к начальным).

ПРИНЦИПЫ ООП, которые здесь применены:
  - Инкапсуляция. Массив данных хранится в ПРИВАТНОМ поле (#accounts,
    #medicines) — снаружи класса к нему обратиться нельзя. Работать с данными
    можно только через публичные методы (all, add, delete, authenticate...).
    Вспомогательный метод #nextId() тоже приватный.
  - Абстракция. Страницам не важно, как именно хранятся данные. Завтра
    заглушку можно заменить запросами на сервер, а страницы менять почти не
    придётся — интерфейс методов останется тем же.
  - Единственная ответственность. Модель описывает данные, сервис работает с
    данными, компонент отображает.
  - Одиночка (singleton): в конце файла сервиса создаётся ОДИН экземпляр
    (export const medicineService = new MedicineService([...])), который
    импортируют все страницы. Поэтому данные везде общие.

МЕТОДЫ AccountService:
  authenticate(login, password) — ищет аккаунт, у которого совпали и логин, и
      пароль (Array.find). Возвращает объект Account или undefined.
  register({login, password, name}) — регистрация:
      1) если какое-то поле пустое -> { ok: false, error: 'Заполните все поля' };
      2) если логин уже есть (Array.some) -> { ok: false, error: 'Такой логин уже занят' };
      3) иначе создаёт Account, добавляет в НОВЫЙ массив, возвращает { ok: true, account }.

МЕТОДЫ MedicineService (повторяют заглушку преподавателя: all/get/add/delete):
  all()            — вернуть весь список;
  get(id)          — найти одну запись (Array.find);
  add({name, price, quantity}) — создать запись с новым id и добавить;
  delete(id)       — убрать запись (Array.filter), вернуть true/false;
  #nextId()        — приватный: максимальный id + 1 (Array.reduce + Math.max).

12. ПОШАГОВЫЕ СЦЕНАРИИ РАБОТЫ
--------------------------------------------------------------------------------
СЦЕНАРИЙ 1. Неавторизованный пользователь открывает сайт.
   1. Браузер открывает "/". currentUser === null.
   2. Маршрут "/" видит null -> <Navigate to="/login" replace />.
   3. Показывается LoginPage. В Nav ссылки «Войти» и «Регистрация».

СЦЕНАРИЙ 2. Авторизация.
   1. Пользователь вводит admin / admin123, нажимает «Войти».
   2. handleSubmit: authenticate нашёл аккаунт.
   3. onLogin(account) -> App: setCurrentUser(account).
   4. navigate('/') -> адрес стал "/".
   5. Теперь currentUser не null, маршрут "/" показывает HomePage.
   6. Nav перерисовался: «Здравствуйте, Администратор» и кнопка «Выйти».

СЦЕНАРИЙ 3. Неверный пароль.
   authenticate вернул undefined -> setError(...) -> красный текст под формой,
   переход не происходит.

СЦЕНАРИЙ 4. Регистрация.
   1. Пользователь заполняет имя, логин, пароль -> «Зарегистрироваться».
   2. register() проверяет поля и уникальность логина, добавляет аккаунт.
   3. navigate('/login') -> пользователь входит под новым аккаунтом.

СЦЕНАРИЙ 5. Добавление лекарства.
   1. В последней строке таблицы вводятся данные, нажимается «Добавить».
   2. AddMedicineForm вызывает onAdd(...) -> HomePage.handleAdd.
   3. medicineService.add(...) добавляет запись (новый id), затем
      setMedicines(medicineService.all()) -> таблица перерисовывается.

СЦЕНАРИЙ 6. Удаление лекарства.
   Кнопка «Удалить» -> onDelete(id) -> HomePage.handleDelete ->
   medicineService.delete(id) -> setMedicines(...) -> строка исчезла.

СЦЕНАРИЙ 7. Выход.
   «Выйти» -> onLogout -> setCurrentUser(null) -> маршрут "/" снова
   перенаправляет на /login, Nav показывает «Войти / Регистрация».

13. VITE И СБОРКА
--------------------------------------------------------------------------------
Vite — инструмент для разработки фронтенда:
  - в режиме dev (npm run dev) запускает локальный сервер, мгновенно
    обновляет страницу при изменении кода (HMR, горячая замена модулей);
  - в режиме build (npm run build) собирает и минимизирует код в папку dist,
    которую можно выложить на хостинг.
Плагин @vitejs/plugin-react (vite.config.js) позволяет Vite понимать JSX.
Проект написан на JavaScript: файлы компонентов имеют расширение .jsx,
остальные — .js. TypeScript (tsconfig, типы) убран.
Импорты вида import Nav from './components/Nav' Vite находит и без
расширения (.jsx/.js).

14. ОГРАНИЧЕНИЯ ПРОЕКТА (ЧЕСТНО)
--------------------------------------------------------------------------------
  - Данные (лекарства, аккаунты) хранятся в памяти браузера и сбрасываются при
    обновлении страницы (F5). Новые зарегистрированные аккаунты пропадают.
  - Состояние «вошёл» (currentUser) тоже хранится в state, поэтому после
    обновления страницы пользователь «выходит» и попадает на /login.
    (Решение на будущее: сохранять пользователя в localStorage или хранить
    сессию на сервере.)
  - Пароли хранятся открытым текстом и проверяются на клиенте. В реальном
    приложении пароли хешируют и проверяют на сервере. Здесь это учебная
    заглушка.
  - Защищённый маршрут скрывает страницу только в интерфейсе; настоящая
    защита данных возможна лишь на сервере.
  - Express-сервер в папке server/ к сайту не подключён.

15. ВОПРОСЫ, КОТОРЫЕ МОГУТ ЗАДАТЬ НА ЗАЩИТЕ, И ОТВЕТЫ
--------------------------------------------------------------------------------
В: Что такое state и зачем он нужен?
О: Это данные компонента, которые React запоминает между перерисовками. При
   изменении state (через функцию set...) React перерисовывает компонент.
   Обычная переменная при перерисовке сбрасывается и интерфейс не обновляет.

В: Где хранится информация об авторизованном пользователе?
О: В state корневого компонента App: const [currentUser, setCurrentUser] =
   useState(null). null — не вошёл, объект Account — вошёл.

В: Почему state пользователя в App, а не в LoginPage?
О: Он нужен нескольким компонентам (Nav, маршруты, LoginPage). Общий родитель
   у них App — «поднятие состояния». LoginPage только сообщает наверх через
   onLogin, что пользователь вошёл.

В: Как реализован переход со страницы авторизации на страницу просмотра?
О: В LoginPage после успешной проверки логина и пароля вызывается
   navigate('/') — функция из хука useNavigate библиотеки React Router.
   Маршрут "/" показывает HomePage (таблицу лекарств).

В: Что такое хук? Какие использованы?
О: Функция React, дающая компоненту дополнительные возможности. Использованы
   useState (хранение данных) и useNavigate (переход между страницами из кода).

В: Почему хуки нельзя вызывать внутри if или цикла?
О: React определяет хуки по порядку вызова. Если порядок меняется между
   перерисовками, состояния перепутаются.

В: Чем Link отличается от обычной ссылки <a>?
О: <a href> перезагружает всю страницу (state теряется). Link меняет адрес и
   показывает другой компонент без перезагрузки — это SPA.

В: Что делает <Navigate>?
О: Перенаправляет на другой маршрут при отрисовке. Используется для защиты
   страницы: если не вошёл — на /login. replace не оставляет лишней записи в
   истории браузера.

В: Что делает <Routes>/<Route>?
О: Routes выбирает один подходящий Route по адресу. Route связывает путь
   (path) и компонент (element).

В: Зачем BrowserRouter?
О: Он включает маршрутизацию, следит за адресной строкой и даёт компонентам
   доступ к Link, useNavigate и т.д. Без него они работать не будут.

В: Что такое props? Можно ли их менять?
О: Параметры, которые родитель передаёт ребёнку. Менять нельзя. Чтобы ребёнок
   повлиял на родителя, родитель передаёт в props функцию (onLogin, onDelete).

В: Зачем key в списке?
О: Чтобы React отличал элементы списка между собой и обновлял только
   изменившиеся строки.

В: Зачем event.preventDefault() в обработчике формы?
О: Браузер при отправке формы по умолчанию перезагружает страницу. Мы это
   отменяем и обрабатываем отправку сами.

В: Почему при добавлении в массив создаётся новый массив ([...old, item])?
О: React сравнивает ссылки. Если изменить тот же массив, ссылка не изменится
   и перерисовки не будет. Новый массив = новая ссылка = перерисовка.

В: Что такое управляемое поле ввода?
О: Поле, значение которого хранится в state (value={x}) и обновляется в
   onChange. React всегда знает содержимое поля.

В: Какие принципы ООП применены?
О: Инкапсуляция (приватные поля #accounts/#medicines, доступ через методы),
   абстракция (страницы не знают, как хранятся данные), разделение
   ответственности (модель/сервис/компонент), одиночка (один экземпляр
   сервиса на всё приложение).

В: Чем «умный» компонент отличается от «глупого»?
О: «Умный» (HomePage) управляет данными и state. «Глупый» (MedicineTable,
   Nav) только отображает полученные props и сообщает о событиях наверх.

В: Зачем нужны сервисы-заглушки?
О: Настоящего сервера нет. Заглушка имитирует его (те же методы all/get/add/
   delete), поэтому позже её можно заменить реальными запросами.

В: Почему не использован useEffect?
О: Данные берутся из заглушки синхронно. useEffect нужен для побочных
   эффектов, например загрузки с сервера.

В: Что произойдёт при обновлении страницы?
О: Всё состояние сбросится: пользователь выйдет, добавленные лекарства и
   новые аккаунты пропадут. Чтобы сохранять — нужен localStorage или сервер.

В: Чем Vite отличается от Create React App?
О: Vite быстрее: в разработке не собирает всё приложение целиком, а отдаёт
   модули браузеру по требованию, и имеет мгновенное обновление (HMR).

В: Что такое SPA?
О: Одностраничное приложение: страница загружается один раз, а «переходы»
   выполняет JavaScript, подменяя содержимое без перезагрузки.
